**建议修改**：
- [ ] 核心阶段只保留"重代码：Java @Tool 注解 Spring Bean"
- [ ] 零代码和轻代码移到扩展点，标注"MCP Client 就绪后启用"
- [ ] 验收标准删掉 MCP Server 相关条目，替换为 Java @Tool 注解的验收
- [ ] 技术方案 §六模块 3 删掉 MCP Client 技术要点
- [ ] 4 周计划 W3 移除 MCP 相关 Task

## 问题 4："热加载"在四个模块里出现了，但机制完全不同

**位置**：
- 需求分析模块 1："支持运行时增删 Provider（热加载，不重启底座）"
- 需求分析模块 3 扩展点："热加载：文件系统监听 agents/ 目录变更"
- 需求分析模块 4 扩展点："mcp_servers.yaml 热加载"

**问题**：三个"热加载"，三个不同机制——Provider 热加载要重建 ChatModel 实例、Agent 热加载要重新扫描目录和解析 YAML、MCP 热加载要重新建立 JSON-RPC 连接。技术方案里没有设计统一的配置变更事件总线或热加载调度器。三个模块各自实现自己的热加载 = 三套文件监听器 + 三套重载逻辑 = 互相踩脚。

**建议修改**：
- [ ] 核心阶段：砍掉所有热加载。Provider 变更需要重启。Agent 变更需要重启。MCP 变更需要重启
- [ ] 模块 1：删掉"支持运行时增删 Provider"，改扩展点为"热加载：监听配置变更 → 重建 ChatModel 实例（扩展阶段，需统一事件总线）"
- [ ] 模块 3 扩展点：改"热加载"描述为"扩展阶段，需统一事件总线"
- [ ] 模块 4 扩展点：删掉"mcp_servers.yaml 热加载"
- [ ] 技术方案 §十四 待决议事项加一条："统一配置热加载机制"
